# 从零到可用：Simply Piano 会员解锁完整记录

这份文档记录了从「发现会员校验接口」到「在两台设备上配好代理规则」的完整过程，
包括所有踩过的坑。下次换设备、换 App 版本、或者帮别人配，照着这个走就行。

---

## 一、先搞清楚原理

Simply Piano 的会员状态不是存在本地的，是服务端说了算。

App 在**登录时**会请求一个接口，服务端返回这个账号的会员信息（JSON），
App 拿到之后决定「你是不是高级会员、能解锁多少内容」。

所以整个方案只有三步：

```
① 让代理软件能解密 HTTPS（MITM）
② 拦住那个接口的响应，把会员字段改掉
③ 让 App 重新请求一次（重新登录）
```

任何一步断了，表现都是「配置看着没问题，但完全没效果」。
后面的所有排查都是围绕这三步来的。

---

## 二、怎么找到关键接口

### 2.1 抓包

用 Quantumult X / Shadowrocket 的抓包功能，或者 Stream、Charles、Proxyman。

操作：开始抓包 → 打开 App → 退出登录 → 重新登录 → 停止抓包。

### 2.2 找可疑请求

Simply Piano 的请求量不大，登录过程中最显眼的就是：

| 域名 | 说明 |
|---|---|
| `asla.joytunes.com` | 主站 API（CloudFront 分发） |
| `alicdn.joytunescn.com` | 国内 CDN 节点 |

关键路径：

```
/server/asla/accounts/accountAuthenticate
/server/asla/accounts/loginToAccountOfRestoredPurchase
```

- `accountAuthenticate`：登录/鉴权，**会员信息就在这里**
- `loginToAccountOfRestoredPurchase`：恢复购买，主要返回错误信息

### 2.3 怎么确认是它

用 curl 直接打一下（不需要登录）：

```bash
curl -X POST -H 'Content-Type: application/json' \
  -d '{"username":"a@b.com","password":"x"}' \
  https://asla.joytunes.com/server/asla/accounts/accountAuthenticate
```

返回：

```json
{"error":null,"accessTokenValid":false}
```

能看到明文 JSON、接口活着，就说明这条路可行。

## 三、怎么看到登录后的真实响应

未登录的响应看不到会员字段，必须**登录后**看。有两种办法：

### 3.1 方法一：探针脚本（推荐）

写一个只弹通知、不改数据的脚本，挂到那个接口上：

```js
var raw = $response.body || "";
var out = [];
var obj = null;
try { obj = JSON.parse(raw); } catch (e) { obj = null; }

if (!obj) {
  out.push("非JSON: " + String(raw).substring(0, 120));
} else {
  out.push("顶层键: " + Object.keys(obj).join(","));
  var RE = /role|member|subscri|premium|trial|plan|iap|product|entitle|access|tier|expire|renew|remain|home|bundle/i;
  var seen = [];
  (function walk(o, path) {
    if (!o || typeof o !== "object") return;
    for (var k in o) {
      var v = o[k], p = path ? path + "." + k : k;
      if (v && typeof v === "object") { walk(v, p); continue; }
      if (RE.test(k)) seen.push(p + "=" + JSON.stringify(v));
    }
  })(obj, "");
  if (seen.length) out.push(seen.join("\n"));
}

try { $notify("SP Probe", "拦截成功", out.join("\n")); } catch (e) {}
$done({ body: raw });
```

**注意**：必须打开 iOS 通知权限（设置 → 通知 → Quantumult X / Shadowrocket → 允许）。

### 3.2 方法二：整个 body 打出来

如果探针的字段过滤漏了什么，就把 body 前 300~800 字符直接弹出来：

```js
var body = $response.body || "";
var url = $request.url || "";
$notify("SP Debug", url.replace(/^https?:\/\//, "").split("?")[0], String(body).substring(0, 300));
$done({ body: body });
```

## 六、改写脚本

```js
var raw = $response.body || "";
var obj;
try { obj = JSON.parse(raw); } catch (e) { $done({ body: raw }); }

var IAP = "com.joytunes.asla.oneyearpremiummembership_trial_180_mpma_fp_5profiles_bundle";

function set(o, k, v) {
  if (!o || typeof o !== "object") return;
  o[k] = v;
}

if (obj && obj.accountInfo) {
  var m = obj.accountInfo.membershipInfo;
  if (m) {
    set(m, "membershipType", "JOYTUNESBUNDLE");
    set(m, "membershipTier", "premium_home");
    set(m, "membershipDescription", "高级会员");
    set(m, "profilesAccess", "FAMILY");
    set(m, "planDuration", "oneyear");
    set(m, "daysRemaining", 366);
    set(m, "autoRenewable", 1);
    set(m, "isAutoRenew", 1);
    set(m, "isTrialPeriod", 0);
    set(m, "dateStarted", "2023-10-14");
    set(m, "currentIapID", IAP);
  }
}

if (obj && obj.profilesList && obj.profilesList.length) {
  for (var i = 0; i < obj.profilesList.length; i++) {
    var p = obj.profilesList[i];
    if (p.privileges && p.privileges.HomeConnection) {
      set(p.privileges.HomeConnection, "homeMembershipTier", "premium_home");
    }
    set(p, "isPremium", true);
  }
}

$done({ body: JSON.stringify(obj) });
```

> 也可以不用脚本，用 QX 原生的 `url response-body <正则> response-body <替换>` 做字符串替换，
> 但脚本方式更可控，也方便加日志。

## 七、Quantumult X 配置

### 7.1 资源文件

```ini
[mitm]
hostname = asla.joytunes.com, alicdn.joytunescn.com

[rewrite_local]
^https?://(asla\.joytunes\.com|alicdn\.joytunescn\.com)/server/asla/accounts/accountAuthenticate url script-response-body https://raw.githubusercontent.com/Dsimpson-man/simplypiano/main/sp_unlock_v2.js
```

### 7.2 导入

1. QX → 风车 → 重写 → 规则资源 → `+`
2. 粘贴资源地址
3. 打开资源开关

### 7.3 必须开的开关

1. 首页 **重写** 开关
2. 首页 **MitM** 开关
3. 风车 → 设置 → MitM → 生成/安装证书
4. **iOS 设置 → 通用 → 关于本机 → 证书信任设置 → 打开 QX 证书**

## 八、Shadowrocket 配置

### 8.1 模块文件

```ini
#!name=Simply Piano Premium
#!desc=Simply Piano 高级会员解锁

[Script]
http-response ^https?://(asla\.joytunes\.com|alicdn\.joytunescn\.com)/server/asla/accounts/accountAuthenticate script-path=https://raw.githubusercontent.com/Dsimpson-man/simplypiano/main/sp_unlock_v2.js, requires-body=1, timeout=60

[MITM]
hostname = asla.joytunes.com, alicdn.joytunescn.com
```

### 8.2 导入

**不要在小火箭里「从 URL 添加」**——这个请求不走代理，`raw.githubusercontent.com` 会超时。

正确做法：用 **Safari 打开模块地址**，会弹出「在 Shadowrocket 中打开」，点一下即可。

### 8.3 必须开的开关

1. 模块开关
2. 设置 → HTTPS 解密
3. 安装证书 → 去系统设置安装描述文件
4. **iOS 设置 → 通用 → 关于本机 → 证书信任设置 → 打开证书**

## 九、配置文件模式的两个坑

如果你用的是 `.conf` 配置文件（不是全局代理），还有两个额外问题：

### 9.1 配置文件会覆盖模块的 MITM 域名

配置文件里只要存在 `[MITM]` 段，就会替换掉模块声明的 hostname 列表。

必须在配置文件里补上：

```ini
[MITM]
hostname = %APPEND% asla.joytunes.com, alicdn.joytunescn.com
```

> `%APPEND%` 表示追加。但**小火箭的配置文件不一定支持这个语法**，
> 如果不生效，就改成直接列出（会覆盖别的模块，但至少能工作）：
>
> ```ini
> hostname = asla.joytunes.com, alicdn.joytunescn.com
> ```

### 9.2 GitHub 域名要走代理

配置文件模式下，脚本下载也按 `[Rule]` 走。加两条：

```ini
DOMAIN-SUFFIX,githubusercontent.com,🚀 策略选择
DOMAIN-SUFFIX,github.com,🚀 策略选择
FINAL,🚀 策略选择
```

### 9.3 `h2` 参数

```ini
[MITM]
h2 = false
```

`h2 = true` 时个别设备上 MITM 行为不一致，遇到问题先改成 `false`。

## 十、三层排查法（最重要）

出问题时**不要瞎改规则**，按层排查，一层层砍：

### 第 1 层：拦截有没有发生

用一个**不需要脚本**的 `reject` 模块测试：

```ini
[URL Rewrite]
^https?://(asla\.joytunes\.com|alicdn\.joytunescn\.com)/server/asla/accounts/accountAuthenticate reject

[MITM]
hostname = asla.joytunes.com, alicdn.joytunescn.com
```

打开它，然后 App 退出登录 → 邮箱登录。

- **登录失败 / 连接错误** → ✅ 拦截正常
- **登录正常** → ❌ 拦截没生效，去查证书和 MITM 开关

这一步能排除掉 80% 的问题，因为它是唯一不依赖脚本下载的测试。

### 第 2 层：脚本有没有跑

用探针脚本（第三节）。有通知 = 脚本跑了；没通知 = 脚本没下载/没执行。

### 第 3 层：改写有没有生效

探针通知里看 `membershipType` 的值：

- `FREE` → 改写没执行
- `JOYTUNESBUNDLE` → 改写生效了，问题在 App 缓存（重新登录）

## 十一、踩坑清单

| # | 坑 | 表现 | 解决 |
|---|---|---|---|
| 1 | `[Rewrite]` 不是有效段落 | 规则完全不生效 | QX 用 `[rewrite_local]`，小火箭用 `[Script]` |
| 2 | 正则里的点没转义 | 误匹配 | 写 `joytunes\.com` |
| 3 | MitM / 重写开关没开 | 配置正常但无效果 | 打开两个开关 |
| 4 | 证书只装了没信任 | 同上 | 系统「证书信任设置」里打开 |
| 5 | 远程脚本下载失败 | 静默不执行 | 换源 / 用本地脚本 |
| 6 | 脚本更新后客户端缓存 | 改完没变化 | 换文件名，或删了重新加 |
| 7 | URL 正则写太宽 | 退出登录报连接错误 | 精确匹配到具体接口 |
| 8 | Apple 登录被拦 | 登录报服务器错误 | 改用邮箱登录 |
| 9 | App 缓存账号信息 | 改完没变化 | 退出登录再登录 |
| 10 | 配置文件覆盖模块 MITM | 模块加了没用 | 配置文件加 `hostname = %APPEND% ...` |
| 11 | 小火箭从 URL 加模块超时 | 导入失败 | 用 Safari 打开导入 |
| 12 | JSON 重新序列化改变结构 | App 校验失败 | 优先用字符串替换，或严格按原结构改 |

## 十二、多设备

**配置和证书都是每台设备独立的，不会同步。**

换到新设备（iPad、另一台手机）时必须重做：

1. 添加模块 / 资源
2. 安装证书 + 在「证书信任设置」里打开
3. 检查配置文件里的 `[MITM]` hostname
4. App 里**退出登录 → 重新登录**

任何一项没做，表现都是「另一台设备能用，这台不行」。

---

## 十三、验证清单

配完之后，按这个顺序验证：

- [ ] 小火箭 / QX 已连接
- [ ] 重写开关打开
- [ ] MitM 开关打开
- [ ] 证书已安装（系统「VPN与设备管理」里能看到描述文件）
- [ ] 证书已信任（「证书信任设置」里开关是开的）
- [ ] 模块 / 资源开关打开
- [ ] 配置文件里有 hostname（配置模式下）
- [ ] App 用**邮箱**登录
- [ ] 登录后**退出再登一次**

全打勾还不生效，就跑第十节的三层排查。
